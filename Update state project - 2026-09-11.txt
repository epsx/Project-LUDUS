  x64 layout audit:
    sizeof(cGlobalPad) = 32
    sizeof(cPlatPad)   = 32
    sizeof(PadMonkey)  = 232

  Important:
    Retail hard-coded allocation sizes were 0x1C for cPlatPad and
    0xD8 for PadMonkey. Those are too small for the MSVC x64 layouts,
    so TARGET_PC now allocates with sizeof(...) while GameCube keeps
    the original retail constants.

  Retail PAD callback model:
    SISetSamplingRate(0)
    PADSetSamplingCallback(VBlankPadUpdate)

  Current PC decision:
    Aurora does not expose the exact retail SISetSamplingRate /
    PADSetSamplingCallback model, so the PC port does not fake those APIs.
    Instead, VBlankPadUpdate() is called explicitly once per native frame
    before nlTaskManager::RunAllTasks().

    A PS4 controller will be connected when that stage is reached.

High-level interpretation — 11.09.2026

  Project LUDUS has progressed from merely restoring the task manager
  into a substantially audited reconstruction of the retail task graph.

  The native PC executable now has:
    - stable Aurora/WebGPU platform bring-up
    - retail filesystem/config startup
    - global texture metadata loading
    - EventManager + nlTaskManager
    - real retail-derived pad/input runtime
    - active task dispatch every native frame
    - restored initial retail state transition semantics
    - integrated ClockUpdate / LoadingManager / PlatPadUpdate /
      DispatchEvents / ComUpdate task paths
    - focused validated wrappers for WorldUpdate / ParticleUpdate /
      FrontEnd / Tweaker / AudioUpdate / EndFrame

  The main conclusion from the latest audit is architectural:
  the remaining task graph cannot be completed safely by adding isolated
  registrations one by one.

  Render-related tasks are blocked by frame ownership:
    Aurora currently owns:
      aurora_begin_frame()
      ...
      aurora_end_frame()

    while the retail graph expects:
      BeginFrameTask
      GameRenderTask
      ParticleUpdateTask
      EndFrameTask

  FE/world-related tasks are blocked by missing production runtime wiring:
    src/Game/FE/feManager.cpp
    src/Game/WorldManager.cpp
    were confirmed not to be wired into the main PC target.

  AudioUpdate is blocked because the real:
    src/Game/Audio/audio.cpp
  implementation is not yet part of the main PC runtime.

  Tweaker remains deferred because the retail g_bTweaking lifecycle/global
  is not yet ported.

  The largest gap before Prima Lux remains genuine rendering:
    real retail render payloads must eventually flow through the native
    WebGPU path, with frame lifecycle ownership reconciled correctly.
