  x64 layout audit:
    sizeof(cGlobalPad) = 32
    sizeof(cPlatPad)   = 32
    sizeof(PadMonkey)  = 232

  Important:
    Retail hard-coded allocation sizes were 0x1C for cPlatPad and
    0xD8 for PadMonkey. Those are too small for the MSVC x64 layouts,
    so TARGET_PC now allocates with sizeof(...) while GameCube keeps
    the original retail constants.

  Retail PAD callback model:
    SISetSamplingRate(0)
    PADSetSamplingCallback(VBlankPadUpdate)

  Current PC decision:
    Aurora does not expose the exact retail SISetSamplingRate /
    PADSetSamplingCallback model, so the PC port does not fake those APIs.
    Instead, VBlankPadUpdate() is called explicitly once per native frame
    before nlTaskManager::RunAllTasks().

  Controller validation:
    Real end-to-end physical controller validation is still pending.
    A PS4 controller will be connected when that stage is reached.

High-level interpretation — 08.09.2026

  Project LUDUS has moved beyond simple startup and pad initialization
  into restoration of the real retail task-manager execution model.

  The native PC executable now has a stable Aurora/WebGPU platform,
  retail filesystem/config startup, global texture metadata loading,
  core managers, audio-startup validation, real retail-derived pad/input
  code, a native frame polling bridge, and active nlTaskManager dispatch.

  The initial retail task state semantics are now restored:
    Startup(0x10000)
      → SetNextState(skipfe ? 2 : 4)
      → transition committed on the first RunAllTasks()

  PC input processing is no longer called as an isolated ad-hoc update.
  It runs through a registered nlTask, and its runtime behavior has been
  validated across the initial state transition.

  The next frontier is deliberately small and architectural:
    restore ClockUpdateTask at retail priority 5.

  This is preferable to jumping directly into FixedUpdate / WorldUpdate /
  GameRender, because those tasks pull in much larger gameplay and
  simulation dependency surfaces.

  The largest remaining gap before Prima Lux is still rendering:
  converting/uploading the real GameCube texture/render payloads into
  the native WebGPU path and continuing the retail task/startup chain far
  enough to produce the first genuine rendered game frame.
