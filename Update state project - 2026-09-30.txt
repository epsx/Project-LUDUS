Architectural conclusion — updated 30.09:

  The FE lifecycle is no longer purely theoretical / deferred.

  A real subset is now active in production and renders retail FE scenes.

  The important remaining distinction is:

    FE bootstrap / scene runtime
      -> now active

    full gameplay/world lifecycle
      -> still incomplete

  Therefore WorldUpdate / FixedUpdate should STILL NOT be forced into
  production merely because the FE path has advanced.


Render/frame ownership remains a separate frontier:

  Aurora currently owns:
    aurora_begin_frame()
    ...
    aurora_end_frame()

  Retail expects:
    BeginFrameTask
    GameRenderTask
    ParticleUpdateTask
    EndFrameTask

  This still needs an explicit ownership/reconciliation design.


WorldUpdate remains intentionally deferred.

Retail behavior:

  if current state == 1 and FE state != start screen:
      WorldManager::UpdateWorld(0.f)
  else:
      WorldManager::UpdateWorld(dt)

State mask:
  0x20013

Contains:
  0x20000
  0x10
  0x2
  0x1

Does NOT contain:
  0x4

Critical lifecycle conclusion remains:

  DO NOT add null guards merely to hide missing world lifecycle ownership.
  DO NOT integrate WorldUpdate into production prematurely.
